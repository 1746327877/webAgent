# 08 监控与可观测性

## 8.1 自研 spans 的取舍（面试讲点）

Langfuse / Phoenix 功能强大但集成是黑盒；自研统一 `spans` 表（[[02-数据库设计]]）约 200 行代码即可覆盖本项目全部观测需求，且**数据建模能力是求职项目最想展示的东西**——"讲得清"比"用得多"值钱。

## 8.2 埋点点位（一次埋点，处处可用）

| 位置 | span 类型 | 记录内容 |
|---|---|---|
| `provider.chat_stream` 前后 | `llm` | model、完整 messages、usage（来自 Ollama done 帧）、首 token/总耗时 |
| `execute_tool` | `tool`（parent=llm span） | 工具 slug、入参、输出（截断 32KB）、耗时、状态 |
| RAG 检索 | `retrieval` | kb_ids、query、双通道各自命中与得分、融合后 top_k |
| ModelManager 切换 | `model_switch` | from/to、加载耗时（同时写 `model_events` 时序表） |
| HTTP 中间件 | —（轻量内存计数） | 请求数/状态码/耗时 → 错误率、QPS |

## 8.3 Token 与成本口径

- usage 直接取 Ollama done 帧：`prompt_eval_count` / `eval_count` / `total_duration` / `eval_duration`。
- 成本三视角（仪表盘切换 chip）：
  1. **Token 量**（原始）；
  2. **等效成本 $**：`models.reference_price_in/out`（$/1M tokens，本地模型填市场等效参考价，公式 `Σ(pt×pin + ct×pout)/1e6`）；
  3. **GPU 时间**：`total_duration` 求和——本地部署讲"电费/时间成本"更真实。

## 8.4 聚合视图（仪表盘不扫全表）

```sql
CREATE MATERIALIZED VIEW mv_metrics_hourly AS
SELECT date_trunc('hour', started_at)      AS hour,
       agent_id,
       count(*)                            AS llm_calls,
       count(*) FILTER (WHERE status <> 'ok') AS errors,
       percentile_disc(0.95) WITHIN GROUP (ORDER BY duration_ms) AS p95_ms,
       COALESCE(sum(prompt_tokens), 0)     AS prompt_tokens,
       COALESCE(sum(completion_tokens), 0) AS completion_tokens,
       COALESCE(sum(prompt_tokens * m.reference_price_in
                  + completion_tokens * m.reference_price_out) / 1e6, 0) AS est_cost_usd,
       sum(duration_ms)                    AS gpu_ms   -- duration_ms 列见 [[02-数据库设计]]
FROM spans s
LEFT JOIN models m ON m.name = s.model
WHERE s.type = 'llm'
GROUP BY 1, 2;

-- 智能体活跃排行：近 7 天 llm 调用数 / token 数降序
-- 定时任务每分钟 REFRESH MATERIALIZED VIEW mv_metrics_hourly
```

## 8.5 阈值告警

- `alert_rules`：`metric ∈ {error_rate, p95_latency, daily_tokens, vram_usage, model_switch_freq}` + operator + threshold + window_minutes。
- ARQ 任务每分钟评估：窗口内计算指标 → 超阈值且该规则**未处于已触发态** → 写 `alert_events`（带 5min 冷却防刷屏）。
- 通知：后台铃铛红点 + 仪表盘横幅（个人项目不做短信/钉钉，预留 webhook 字段）。

## 8.6 前端可视化（ECharts）

| 页面 | 图表 |
|---|---|
| 全局仪表盘 | 指标卡片行（今日请求/Token/成本/错误率/p95）；24h~30d 时序折线（双 y 轴：请求数+Token）；智能体活跃排行（横向柱状）；Token 分布（饼图：按智能体/按模型）；显存曲线 |
| 会话详情 | **span waterfall 时间线**：横向甘特条（起点=相对时间，长度=duration），颜色区分 llm/tool/retrieval/model_switch；点击条 → 侧滑抽屉展示 input/output JSON 树 + usage + 耗时拆解（排队/加载/首 token/生成） |
| 工具调用日志 | 可筛选表（类型/状态/智能体/时间范围）+ 行内 JSON 预览 + **CSV 导出**（`GET /admin/export.csv`，流式生成防大结果 OOM） |
| 原始请求/响应 | JSON 树查看器（折叠长字段），供 debug 模式逐字对拍 |

## 8.7 数据保留

- `spans` 90 天、`model_events` 30 天、HTTP 计数 7 天；每日 ARQ 任务清理。
- `messages.blocks` 随会话长期保留（用户数据，不属于遥测）。

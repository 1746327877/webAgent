# 19 · 文档转换 Skill

> 状态：设计已定，已实施
> 关联：`12-扩展能力与MCP.md`（Skill = 指令包）、`05-知识库RAG.md`（附件文本注入）、`09-前端交互设计.md`

## 19.1 背景与目标

用户上传文档后经常想要"换一种格式"：PDF 转 Markdown、段落转表格、带标记的文本转纯文本。这类工作**不需要外部服务**，本质是模型对已经在上下文里的文本做结构重排。

目标：新增一个内置 Skill `doc_convert`，让绑定了它的智能体稳定地按目标格式输出、保留结构、且**不编造原文没有的内容**。

## 19.2 决策（假设，可返工）

| 事项 | 决策 | 理由 |
|---|---|---|
| 形态 | **纯 Skill（指令包）**，不新增工具、不新增依赖 | `12` 已定：Skill 就是注入 system prompt 的指令；转换靠模型完成 |
| 输入来源 | 复用既有附件文本注入（`runtime._document_context_notes`）与用户直接粘贴的内容 | 不重复造"读文档"能力 |
| 不做的部分 | **不产出可下载的转换文件** | 那需要"写附件 + 落盘 + 下载"的新链路，是独立功能；见 §19.5 |
| 结构保真 | 指令里明确：保留层级/列表/表格；无法识别的内容用「（原文缺失）」占位，禁止补写 | 与 `05` 的"引用溯源、不编造"口径一致 |

## 19.3 设计

在 `backend/app/ai/skills.py` 注册：

```python
_register(SkillDef(
    slug="doc_convert",
    name="文档转换",
    icon="📄",
    summary="在 Markdown、表格、纯文本等格式间转换文档内容，尽量保留原有结构。",
    usage="上传文档（pdf/docx/md/txt）后说明目标格式……",
    instructions=(
        "用户要求格式转换时，严格按目标格式输出，不要附加解释性前言或多余总结。"
        "保留原文的层级、列表与表格结构；原文缺失或无法识别的内容用「（原文缺失）」占位，禁止补写。"
        "内容是表格数据时输出 Markdown 表格；要求纯文本时去掉 Markdown 标记但保留换行与缩进。"
        "转换结果较长时分节输出，并在开头用一句话说明来源文件名与目标格式。"
    ),
    examples=[...],
    recommended_tools=[],
))
```

Skill 清单是只读代码清单（`GET /api/v1/capabilities/skills`），前端「扩展能力 → Skill」自动展示；智能体在编辑器里绑定后，`agent_config._compose_prompt` 会把 `instructions` 注入 system prompt。

## 19.4 测试

- `backend/tests/test_capabilities_api.py`：`GET /capabilities/skills` 返回的 slug 含 `doc_convert`；字段完整性与既有校验一致。

## 19.5 已知限制

- **不产出文件**：转换结果只出现在对话里，不能下载为 `.md`/`.csv`。要落地成文件需新增"写附件"能力，另议。
- **转换质量取决于附件文本质量**：附件抽取走 `parsers.extract_text`（不经过 MinerU），扫描件仍是空文本；此时模型只能说明无法识别。
- Skill 需智能体显式绑定才生效（与既有 5 个 Skill 一致）。

## 19.6 决策记录

- 按用户"添加文档转换的 skill"的字面意图实现为 **Skill 指令包**，而不是新增转换工具；文件产出明确排除并记录为限制（假设，可返工）。

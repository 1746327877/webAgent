# 15 · 历史会话多选删除

> 状态：设计已定，实施中
> 关联：`06-会话与消息流.md`、`09-前端交互设计.md`、`14-前端标签页重构.md`

## 15.1 背景与目标

侧栏历史会话目前只能**逐条**删除（每删一条发一次 `DELETE /api/v1/sessions/{id}`）。演示数据有 1000 条会话，逐条删既慢又烦。目标：多选 + 全选一次删除。

## 15.2 决策（已确认）

| 事项 | 决策 |
|---|---|
| 「全选」范围 | **仅当前已加载**的会话（侧栏分页，默认 50 条/页）；不提供"按筛选删全部"，避免误删不可见数据 |
| 归档视图 | **主列表与「查看归档」都支持**多选删除 |
| 删除语义 | 与单条一致：**硬删除**（不可恢复），确认弹窗显示数量 |

## 15.3 后端

新增批量删除接口（不逐条发请求）：

- `POST /api/v1/sessions/bulk-delete`，body `{"ids": [uuid, ...]}`，`ids` 长度 1..500（Pydantic `min_length`/`max_length`）。
- `session_service.delete_sessions(db, user, ids) -> int`：单条 SQL
  `DELETE FROM sessions WHERE user_id = :me AND id = ANY(:ids)`，返回 `rowcount`。
  **他人/不存在的 id 一律忽略**（不报 404），避免批量操作因个别脏 id 整体失败。
- 响应 `{"deleted": n}`。级联删除（messages/attachments/spans）沿用现有 FK `ondelete=CASCADE`；磁盘上的附件文件由既有 `cleanup_orphan_attachments` 回收。

## 15.4 前端

`SessionSidebar` 增加"多选模式"：

- 底部「多选」进入选择模式；进入后**每行左侧出现复选框**，点击整行=切换选中（不再跳转会话）。
- **分组标题旁一个复选框**（置顶 / 今天 / 昨天 / 7 天内 / 更早）：勾选即**整组全选**，取消即整组取消；部分选中显示 `indeterminate`。
  - 这是主要的批量入口：勾"今天"就把今天所有会话选中，可累计勾多个分组。
- 顶部（搜索框下方）显示 `已选 N` + `删除选中`：**删除按钮不放页面底部**。
- **确认就近显示**：点「删除选中」后，同一行变成 `删除 N 条？不可恢复` + `确认删除` + `取消`；不使用浏览器 `confirm()`（那种弹窗出现在页面中上方，体验割裂）。
- 删除成功后 `toast.success` + 失效 `["sessions"]`；若当前正在浏览的会话被删，跳回 `/`。
- 多选模式对主列表与归档视图一视同仁；「全选」只覆盖**已加载**的会话（未加载分页不选，避免误删不可见数据）。
- `api/sessions.ts` 新增 `useBulkDeleteSessions()`（`POST /sessions/bulk-delete`，成功后失效 sessions 查询）。

## 15.5 测试

- 后端 `test_sessions_api.py`：批量删除自己的多条；混入他人 id 时只删自己的、`deleted` 计数正确；`ids` 为空 → 422。
- 前端 `SessionSidebar.test.tsx`：进入多选模式；单选/全选/取消全选；删除调用 `bulk-delete` 且携带已选 id；确认取消则不调用。

## 15.6 已知限制

- 不做"按筛选条件删除全部"（避免一键清库）；全选只覆盖已加载。
- 硬删除不可恢复；不做回收站（与现有单条删除语义一致）。

# 18 · 联网搜索：开箱可用 + 对话级开关

> 状态：设计已定，实施中
> 关联：`13-MinerU与联网搜索MCP.md`（web-search 服务与 MCP 接入）、`12-扩展能力与MCP.md`（MCP 机制）、`06-会话与消息流.md`（SSE 与请求体）

## 18.1 背景与目标

现状：`web-search` 是 compose 服务 + http MCP，但按 `13` §13.5 的决策，它需要用户**手动新建 MCP Server → 测试连接 → 在智能体里逐个勾选工具**才能用。想临时搜一下，门槛偏高。

目标：

1. **开箱可用**：部署方配好 `WEB_SEARCH_MCP_URL` 后，无需任何手动建 MCP，对话即可联网搜索。
2. **对话级开关**：输入框加一个「联网搜索」按钮，点开后该条消息才携带 web-search 工具（默认关闭，按需开启）。

## 18.2 决策（假设，可返工）

| 事项 | 决策 | 理由 |
|---|---|---|
| 与 MCP 手动模型的关系 | **不破坏**；新增"部署级合成绑定"，运行时临时注入，**不写 `mcp_servers` 表、不 seed** | 避免迁移与用户数据污染；`12` §已知限制里"用户可自建 MCP"保持不变 |
| 开关粒度 | **每条消息**（与 `model_override` 同构），不持久化 | 改动最小、语义直观；刷新后回到默认关闭 |
| 未配置 URL | 按钮禁用并说明原因；后端收到 `web_search=true` 也只是不注入 | 失败降级，不报错 |
| 与智能体已绑定 web-search 的关系 | 按 `server_name` 去重：已绑过就不重复注入 | 避免同名工具碰撞（`build_mcp_tools` 会加 `_1` 后缀，但语义重复） |
| 探测时机 | 首次需要时探测并**缓存 300s**；探测失败记 warning 并本轮降级 | 每条消息都探测会拖慢首包 |
| `regenerate` / OpenAI 兼容端点 | **不透传**该开关（同 `model_override` 现状） | 记为已知限制，不在本次扩张 |

## 18.3 设计

### 18.3.1 配置（`app/core/config.py`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `WEB_SEARCH_MCP_URL` | 空 | 为空=不支持联网搜索。Docker 后端填 `http://web-search:3000/mcp`，本地开发填 `http://localhost:3300/mcp` |

### 18.3.2 合成绑定（新增 `app/ai/web_search.py`）

- `SERVER_NAME = "web-search"`；`is_enabled()` 判断 URL 非空。
- `async def binding() -> McpBinding | None`：
  - 探测 `GET`/`initialize` + `list_tools`（复用 `mcp_service.probe`），把结果缓存 300s；
  - 成功→返回合成 `McpBinding`（`server_id` 用固定命名空间 UUID，`config` 形如 `mcp_service.server_config` 的 http 形态，`tools` 为探测结果）；
  - 失败/未配置→返回 `None`，记 warning。
- 模块级缓存需注释**生命周期与并发假设**（进程内、单事件循环、TTL 到期重建），符合 `AGENTS.md` §2.3 对全局可变状态的要求。

### 18.3.3 运行时注入（`app/ai/runtime.py`）

- `run_generation(...)` 新增 `web_search: bool = False`。
- 在 `build_mcp_tools` 之前：若开关为真且 `web_search.binding()` 返回绑定，且 `cfg.mcp_bindings` 里没有同名 `server_name`，则并入 `cfg.mcp_bindings`。
- 其余工具装配、ReAct 循环、span 记录不变。

### 18.3.4 请求透传（`app/api/v1/sessions.py`）

- `MessageIn` 新增 `web_search: bool = False`；`post_message` 传给 `run_generation`。

### 18.3.5 状态查询（`app/api/v1/capabilities.py`）

- 新增 `GET /capabilities/web-search` → `{enabled, url, healthy, tools, error}`；前端据此决定按钮是否可用（30s 轮询，同 `parser` 面板模式）。

### 18.3.6 前端

- `stores/composer.ts` 新增 `webSearch: boolean` + `setWebSearch`。
- `components/chat/Composer.tsx` 工具栏（`ModelSelector` 旁）新增一个开关按钮；`disabled` 时给 tooltip 说明未配置。
- `components/chat/ChatView.tsx` 的 `send` 请求体在开关开启时带上 `web_search: true`（与 `model_override` 的"仅在显式开启时上报"一致）。

## 18.4 测试

| 层 | 用例 |
|---|---|
| `backend/tests/test_web_search.py`（新增） | 未配置 → `binding()` 返回 None；探测成功 → 返回合成绑定且带 tools；探测失败 → None 且不抛；TTL 缓存生效（二次调用不重复探测） |
| `backend/tests/test_sessions_api.py`（改/加） | 请求带 `web_search=true` 透传到 `run_generation` |
| `backend/tests/test_rag_runtime.py` 或新文件 | 开关开启且同名已绑定 → 不重复注入；未配置 → 不注入且生成正常 |
| 前端 vitest | composer store 开关；Composer 按钮切换；ChatView 请求体带/不带 `web_search` |

## 18.5 已知限制

- 开关不持久化，`regenerate` 与 OpenAI 兼容端点不透传（同 `model_override`）。
- 探测结果按 URL 缓存 300s，改了配置需等待过期或重启。
- 合成的 `server_id` 是固定 UUID，只用于分组/去重，不代表数据库行。
- web-search 服务本身无鉴权（`13` §13.5），故合成绑定 headers 为空。

## 18.6 决策记录

- 采用"部署级合成绑定 + 每消息开关"，而非自动 seed `mcp_servers` 行：避免迁移与用户数据污染，且不改变"MCP 由用户手动接入"的既有决策（假设，可返工）。
- 不改 `regenerate` / OpenAI 兼容端点，控制本次改动范围。

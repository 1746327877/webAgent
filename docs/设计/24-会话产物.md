# 24 · 会话产物（导出与预览）

> 状态：设计已定，实施中（阶段一：导出 Markdown + 右侧预览）
> 关联：`06-会话与消息流.md`（消息与 blocks）、`09-前端交互设计.md`（右侧抽屉）、`23-语音转写MCP.md`（转写块也会进纪要）

## 24.1 背景与目标

用户希望"会话能产出文件，右侧能看到并预览"。这里有个必须先说清的前提：

**LLM 本身不能生成文件**——它只输出文本。要出现"产物"，必须先有**产出通道**。所以功能拆成两块：产物从哪来、右侧怎么预览。

阶段一（本次）先做**平台导出**：把当前会话导出成 Markdown，右侧产物区列出并预览。后续阶段再支持"工具/MCP 产出文件"与 Word/PDF。

## 24.2 决策（已确认）

| 事项 | 决策 | 理由 |
|---|---|---|
| 产物来源 | 阶段一：**平台导出 Markdown**；`source` 字段预留 `tool`/`mcp` | 零新依赖、立刻可用；模型不能写文件 |
| 存储 | **新增 `artifacts` 表**，不塞进 `attachments` | 附件会被孤儿回收（`message_id IS NULL` 且超时）；产物没有 message_id，复用会被误删 |
| 落盘 | 与附件同一约定：`settings.upload_dir/{uuid}.{md}` | 复用既有的目录/挂载与越界防护写法 |
| 下载/预览鉴权 | 走既有鉴权接口（`apiFetch` 带 token），前端取 blob/text 再渲染 | 直接给 `<iframe src>`/`<img src>` 不会带 token，会 401 |
| 预览能力 | 文本/Markdown → 直接渲染；PDF → `<iframe>`；图片 → `<img>`；其它 → 提示下载 | 浏览器原生能力，不引依赖 |
| Word 预览 | **本期不做**；将来用 `mammoth` 转 HTML | 浏览器不能原生预览 docx；mammoth 是纯 Python 轻依赖（用户确认） |

## 24.3 设计

### 24.3.1 数据模型（`artifacts`）

| 字段 | 说明 |
|---|---|
| `id` | PK |
| `session_id` | FK → `sessions.id`，`ondelete=CASCADE`，索引 |
| `source` | `export` / `tool` / `mcp` |
| `filename` | 展示与下载用的文件名（会话标题清洗后 + `.md`），**不含路径** |
| `mime_type` | 如 `text/markdown` |
| `size_bytes` | 字节数 |
| `file_path` | 落盘名 `{uuid}.{ext}`，落在 `settings.upload_dir` |
| `created_at` | 创建时间（列表按它倒序） |

### 24.3.2 接口（`app/api/v1/artifacts.py`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/sessions/{sid}/artifacts/markdown` | 导出当前会话为 Markdown，返回产物行（201）；内容过大返回 413 |
| GET | `/sessions/{sid}/artifacts` | 产物列表（新的在前） |
| GET | `/artifacts/{aid}` | 下载/预览原文（`FileResponse`） |
| DELETE | `/artifacts/{aid}` | 删除产物（行 + 磁盘文件，204）；别人的产物 404 |

归属校验与附件一致：会话/产物不属于当前用户一律 404（不泄露存在性）；`file_path` 含路径分隔符一律 404。

### 24.3.3 导出内容（`artifact_service.render_session_markdown`）

```
# {会话标题}
- 会话 ID / 导出时间 / 消息数
---
## 我 / ## 助手（逐条）
  text 块 → 原文
  transcript 块 → "> 🎙️ 语音转写（文件名）：内容"
  citation 块 → 汇总为"引用来源"列表（[1] java.md p2）
  thinking 块 → 跳过（思考链不进纪要）
```

- 文件名清洗：路径分隔符与控制字符替换为 `_`，最长 80 字符，空标题回落"会话纪要"。
- 大小上限 5MB（纯文本防御，超限 413）。

### 24.3.4 前端

- `api/artifacts.ts`：`useArtifacts(sessionId)`、`useExportMarkdown(sessionId)`（成功后失效列表）、`artifactFileUrl(id)`、`downloadArtifact()`（blob + 临时 `<a>`，因为下载也要带 token）。
- `components/chat/ArtifactPanel.tsx`：右侧产物区——列表（文件名 + 大小，选中高亮）+ 预览区（Markdown 渲染 / PDF iframe / 图片 / 其它提示下载）+ 下载按钮；切换或卸载时 `revokeObjectURL`。
- `ChatView`：头部新增「导出纪要」（导出成功后自动打开产物区）与「产物」开关。

## 24.5 已知限制与后续

- **只有 Markdown 一种产物**：PDF/Word 需要引入生成依赖（`python-docx` / 报告渲染），未做。
- **Word 预览未做**：将来 `mammoth` 转 HTML（样式有损）。
- **产物不回收**：不像附件有孤儿 GC；删会话会级联删行，但**磁盘文件不清理**（与附件同一现状，后续可做统一清理任务）。
- **导出的是"原始对话"不是"AI 纪要"**：想要结构化纪要靠智能体的提示词（见"会议总结智能体"），导出只是把已有内容落成文件。
- 导出为**同步**操作；超大会话会阻塞请求（当前上限 5MB 内可接受）。

## 24.6 决策记录

- 新增 `artifacts` 表而非复用 `attachments`：避免被附件孤儿 GC 误删（用户确认方向后由本次裁决）。
- 阶段一先做"导出 Markdown"（用户选择），Word 预览将来走 `mammoth`（用户选择）。
- 预览一律走鉴权接口取内容，不直接暴露文件 URL。

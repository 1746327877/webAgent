# 10 部署与简历叙事

## 10.1 本地开发环境搭建

```bash
# 1. Ollama（宿主机，GPU 直通）
winget install Ollama.Ollama
# 系统环境变量：OLLAMA_MODELS=D:\ollama\models   ← 防 C 盘爆满
ollama pull qwen2.5:7b-instruct-q4_K_M
ollama pull deepseek-r1-distill-qwen:7b
ollama pull qwen2.5vl:7b
ollama pull bge-m3

# 2. 基础设施
docker compose up -d postgres redis      # pgvector/pgvector:pg16 + redis:7

# 3. 后端
cd backend && uv sync && uv run alembic upgrade head
uv run python seed.py                    # 演示账号/3个预置智能体/示例知识库
uv run uvicorn app.main:app --reload --port 8000
uv run arq app.workers.WorkerSettings    # 另开终端：异步任务

# 4. 前端
cd frontend && pnpm i && pnpm dev        # http://localhost:5173，Vite 代理 /api → :8000
```

## 10.2 docker-compose（生产形态）

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    environment: { POSTGRES_DB: webagent, POSTGRES_USER: webagent, POSTGRES_PASSWORD: ${PG_PWD} }
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U webagent"], interval: 5s, retries: 10 }
  redis:
    image: redis:7-alpine
  backend:
    build: ./backend                  # python:3.12-slim + uv 多阶段构建
    environment:
      DATABASE_URL: postgresql+asyncpg://webagent:${PG_PWD}@postgres/webagent
      REDIS_URL: redis://redis:6379/0
      OLLAMA_BASE_URL: http://host.docker.internal:11434
    extra_hosts: ["host.docker.internal:host-gateway"]
    depends_on: { postgres: { condition: service_healthy } }
  frontend:
    build: ./frontend                 # node 构建阶段 → nginx 托管 dist + 反代 /api → backend:8000
                                      # nginx 注意：proxy_buffering off（SSE 关键）
    ports: ["${FRONTEND_PORT:-8090}:80"]   # 8090：8080 常被 Steam 的 CEF 调试端口等占用
    depends_on: [backend]
volumes: { pgdata: {} }
```

> **Ollama 不进容器**：Windows GPU 直通繁琐，宿主机跑最稳；容器经 `host.docker.internal` 访问。

## 10.3 简历 bullet（按岗位取舍 3~4 条）

- 基于 **FastAPI + React** 开发本地化多智能体 AI 工作台：SSE 类型化事件协议实现流式对话，ReAct 循环集成 function calling 工具系统，支持 `@` 多智能体接力协作与知识库引用溯源。
- 设计**单 GPU（12GB）显存约束下的模型热切换状态机**（加载/卸载/驱逐/重试 + 乒乓缓解），实现 7B 级 LLM/嵌入/多模态模型按需调度与显存值守监控。
- 构建 **pgvector + jieba 中文全文 + RRF 融合**的混合检索 RAG 管道（异步 Ingest 状态机、引用可溯源），并实现检索过程全链路可解释。
- 自研 **Langfuse 式轻量可观测性体系**：统一 span 模型支撑调用链 waterfall、Token/等效成本/GPU 时间三维计量、物化视图仪表盘与阈值告警。

## 10.4 双项目组合策略（D8 决策）

| 项目 | 周期 | 简历叙事 |
|---|---|---|
| **项目一：自建平台**（本文档主体） | Phase 1，约 8 周 | 证明**从 0 到 1** 的架构设计与实现能力：显存调度状态机、RRF 混合检索、自研可观测性、@接力协议 |
| **项目二：Open WebUI 二开** | Phase 2，约 3~4 周 | 证明**大型代码库协作与最小侵入集成**能力（最接近真实工作形态）：把显存看板 / @接力 / waterfall 中的 1~2 个亮点移植进 18 万行成熟项目 |

- **顺序必须串行且自建先行**：差异化资产优先；二开是"第二次实现"，带着 Phase 1 认知做效率翻倍；避免一人并行双线的上下文切换损耗。
- **Phase 1 期间 Open WebUI 只做三件事**：装来日常用（体验交互细节）、读关键源码当参照（SSE 边界处理、插件体系、混合检索参数）、面试讲选型对比（"我评估过 Open WebUI，因 X/Y/Z 决定自建"——技术决策力本身就是考点）。
- **加分延伸**：Phase 2 若能以 PR 形式回馈上游（挑社区真正想要的能力）并 merge，151k star 项目的 contributor 记录价值极高，立项时评估。

## 10.5 面试 Q&A 预演

| 可能被问 | 答案要点 |
|---|---|
| 为什么 SSE 不用 WebSocket | 单向下行流；代理友好/自动重连/调试简单；控制面走 POST；ChatGPT 同款方案 |
| 12GB 显存怎么跑多模型 | 单槽位状态机 + 接力切换；锁粒度只包切换临界区；乒乓缓解（keep_alive + 切换频率监控）；@协作天然串行 |
| 检索质量怎么衡量 | 双通道互补（语义 vs 关键词）；RRF 免调参；黄金问答集算 recall@k（[[05-知识库RAG]] §5.8）；得分全链路可解释 |
| 工具调用死循环怎么办 | 5 轮上限 + 单工具超时 + 输出截断 + Ollama 原生 tool_calls 协议 |
| Ollama 换 vLLM 要改多少 | 只新增 Provider 实现；Manager 的单槽位属 Ollama 细节已下沉到 Provider；接口清单见 [[01-整体架构与技术栈]] |
| 多用户隔离怎么保证 | repository 层强制注入 owner_id（不靠接口自觉）；子资源 404 化防探测；可选 RLS 兜底 |
| 本地模型"成本"是什么 | Token/等效成本/GPU 时间三视角；面试引出"私有化部署 TCO"话题 |

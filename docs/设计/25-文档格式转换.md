# 25 · 文档格式转换（pdf / docx / md 互转）

> 状态：设计已定，已实施
> 关联：`19-文档转换Skill.md`（本期替换其「不产出文件」的形态）、`24-会话产物.md`（artifacts 表与预览）、`12-扩展能力与MCP.md`（Tool/Skill 注册）、`05-知识库RAG.md`（解析器与上传类型）、`23-语音转写MCP.md`（runtime 层工具拦截先例）

## 25.1 背景与目标

`19` 把「文档转换」实现为一个**纯 Skill 指令包**：模型把附件抽取出的文本按目标格式重排，结果只出现在对话里。它有两个硬限制：

1. **产不出真实文件**——LLM 只输出文本，无法生成 `.docx` / `.pdf`（二进制）。
2. **只能产出文本**——目标格式实际只有 Markdown / 表格 / 纯文本，谈不上「pdf、docx、md 互转」。

本期目标：**新增真实的格式转换能力**，让上传的 `pdf / docx / md / txt` 能互相转成 `md / docx / pdf` 三种可下载文件，并在「产物」区预览（pdf、docx 都要能预览）。

非目标（明确不做，避免范围蔓延）：

- **不接 OCR**：扫描件 PDF（无文本层）仍无法转换，只给出可操作提示。
- **不追求版式高保真**：不复刻字体、字号、颜色、页眉页脚、分栏；只保结构（标题层级、列表、表格、代码块）。
- **不改知识库解析链路**：`05` 的上传/解析/切片不受影响；本期的转换只在对话附件链路上。

## 25.2 决策（已确认）

| 事项 | 决策 | 理由 |
|---|---|---|
| 触发方式 | 新增内置工具 `doc_convert`，由 Skill 指令引导模型调用；真实转换在 **runtime 层拦截** | 与 `transcribe_audio`（`23`）同一模式：只有平台拿得到本轮附件路径与产物落盘能力，模型只负责决定「转什么、转成什么」 |
| 转换引擎 | **纯 Python**：`markdown` + `mammoth` + `reportlab` | 无系统依赖，宿主（`start.ps1 -Local`）与容器行为一致，镜像几乎不增；`pymupdf` / `python-docx` 为既有依赖 |
| 数据流 | md/docx **先转 HTML**，再进统一中间结构 **IR**；pdf 直接进 IR | md↔docx 的结构保真靠成熟库；docx→HTML 与 docx 预览复用同一 `mammoth` 能力，一份事实一处实现 |
| 产物 | 复用 `artifacts` 表，`source="tool"` | 复用 `24` 的落盘约定、下载接口、归属校验与前端预览，不新增表、不新增迁移 |
| docx 预览 | 后端 `mammoth` 转 HTML，前端塞进 `<iframe sandbox srcdoc>` | 浏览器不能原生预览 docx；`sandbox` 禁脚本，天然防 XSS，且**不引入前端依赖**（符合 `AGENTS §2.6`） |
| 绑定要求 | 智能体需同时绑定 `doc_convert` Skill 与 `doc_convert` 工具 | 与既有工具一致（`kb_search` 等）；Skill 的 `recommended_tools` 只是展示建议，不强制绑定 |

## 25.3 设计

### 25.3.1 转换矩阵

来源与目标（目标 `md / docx / pdf`）：

| 源 \ 目标 | md | docx | pdf |
|---|---|---|---|
| **pdf** | pymupdf 抽段落 → IR → md | pymupdf → IR → docx | 不做（pdf→pdf 无意义） |
| **docx** | mammoth→HTML→IR→md | 拒绝（同格式） | mammoth→HTML→IR→pdf |
| **md** | 拒绝（同格式） | markdown→HTML→IR→docx | markdown→HTML→IR→pdf |
| **txt** | 直接作为纯文本 → md | 纯文本 → docx | 纯文本 → pdf |

- 源扩展名沿用附件白名单：`pdf / docx / md / markdown / txt`；目标固定三选一。
- 源与目标同格式：返回「源文件已是该格式」错误，不做无意义复制。

### 25.3.2 数据流

```
本轮附件路径
  ├─ md/markdown ─ markdown 库 → HTML ┐
  ├─ docx ─────── mammoth        → HTML ┤→ html_reader(标准库) → IR
  ├─ pdf ──────── pymupdf ──────────────→ IR（纯文本段落）
  └─ txt ──────── 纯文本 ───────────────→ IR（单段落）
                                              │
                              writers:  md / docx / pdf
                                              │
                              artifact_service 落盘 + artifacts 行(source=tool)
                                              │
                              前端「产物」区：下载 / 预览（md 渲染、pdf iframe、docx HTML）
```

### 25.3.3 中间结构 IR 与模块划分

新增 `backend/app/ai/convert/`，按职责拆小文件（`AGENTS §2.1` 单文件 ≤400 行）：

| 文件 | 职责 |
|---|---|
| `ir.py` | 数据结构：`Span(text, bold, italic, code)`；块类型 `Heading(level, spans)`、`Paragraph(spans)`、`ListBlock(ordered, items)`、`TableBlock(header, rows)`、`CodeBlock(text, language)`、`Quote(spans)`、`PageBreak()` |
| `html_reader.py` | 标准库 `html.parser` 把 HTML 转 IR（`h1–h6` / `p` / `ul,ol` / `table` / `pre,code` / `blockquote` / `hr`；`strong,b`→bold、`em,i`→italic、`code`→code） |
| `readers.py` | `read_source(path, ext) -> list[Block]`：md→`markdown` 库→HTML→IR；docx→`mammoth`→HTML→IR；pdf→`pymupdf` 逐页段落；txt→纯文本段落 |
| `writers.py` | `to_markdown / to_docx / to_pdf`：IR → 目标字节。docx 用 `python-docx`；pdf 用 `reportlab`（`STSong-Light` CID 中文字体，无需字体文件） |
| `__init__.py` | `convert_file(path, src_ext, target) -> ConvertedDoc(data, mime, ext)` 与 MIME 表；未知/同格式/空内容在此统一报错 |

IR 是「读」与「写」的唯一契约：新增一种来源或目标只动一侧，互不影响。

### 25.3.4 工具与 Skill

- **工具**（`app/ai/tools/builtins.py`）：
  ```python
  @tool("doc_convert", "文档转换",
        "把本轮上传的文档转换为指定格式（md/docx/pdf），生成可下载产物",
        category="document", is_system=True)
  async def doc_convert(target: str, name: str = "") -> str:
      """真实转换在 runtime 层拦截（只有平台拿得到本轮附件与产物落盘能力）。"""
  ```
  `target` ∈ `{md, docx, pdf}`；`name` 可选，按**文件名包含**匹配（与 `transcribe_audio` 一致）；留空且本轮只有一个文档附件时直接用它，多个则报错要求指定。
- **Skill**（`app/ai/skills.py` 的 `doc_convert`）：`instructions` 改为「用户要求转成 md/docx/pdf 时调用 `doc_convert` 工具，不要在对话里手动重排整份文档；工具返回后告知产物文件名与下载位置」。`usage`、`summary`、`examples` 同步更新；`recommended_tools=["doc_convert"]`。
- **runtime 拦截**（`app/ai/runtime.py`）：`_execute_tool` 增加 `document_files` 参数；新增 `_run_convert_tool(document_files, parsed, db, session_id)`：校验参数 → 选附件 → 线程池执行 `convert_file`（CPU 重活不阻塞事件循环）→ 建产物 → 返回带文件名的一句话。失败与错误参数**只回填错误结果，不中断生成**（与既有工具一致）。

### 25.3.5 产物与接口

- `artifact_service` 新增 `create_bytes_artifact(db, session, filename, mime, data, source="tool")`：复用 `safe_filename`、`upload_dir/{uuid}.{ext}` 落盘约定与 5MB 防御上限；`create_markdown_artifact` 改为调用它（消除重复）。
- 新增 `GET /artifacts/{aid}/preview`：仅对 docx 返回 `text/html`（mammoth 转换结果）；其它类型 `415`，提示「该类型无需服务端预览」。归属校验与 `/artifacts/{aid}` 一致（别人的产物 404，`file_path` 含分隔符 404）。

### 25.3.6 前端

- `components/chat/ArtifactPanel.tsx`：新增 docx 分支——取 `/api/v1/artifacts/{id}/preview`，把 HTML 放进 `<iframe sandbox srcdoc title={文件名}>`（`sandbox` 无 `allow-scripts`，脚本不执行）；加载失败显示错误而非空白。
- `components/chat/ChatView.tsx`：`runStream` 的 `finally` 里补一次 `invalidateQueries({ queryKey: ["artifacts", targetSession] })`，转换出的产物立即出现在面板。产物区未打开时该 query 非活跃，不会产生额外请求。
- 不新增前端依赖，不改 `ToolArtifacts`（本功能产出的是产物，不是工具图片）。

## 25.4 错误处理与降级

| 场景 | 行为 |
|---|---|
| 本轮无文档附件 | 工具返回「本轮没有可转换的文档附件」，`error` 状态 |
| 多个文档附件且未指定 `name` | 返回可选文件名列表，要求调用方指定 |
| `target` 非法 / 与源同格式 | 返回明确错误与允许的目标格式 |
| 扫描件 PDF（无文本层） | 返回「未提取到文本，可能是扫描件（未接 OCR）」 |
| 转换或落盘异常 | 记录 warning，回填错误结果，不中断本轮生成 |
| 产物超过 5MB | 返回「转换结果过大」，不落盘 |

## 25.6 已知限制

- **扫描件 PDF 不可转**：走 `pymupdf` 文本层，无文本即失败（与 `05` 内置解析同限制；MinerU OCR 不在此链路）。
- **PDF 来源结构有损**：只还原段落文本，不识别标题层级与表格；表格结构只在 md、docx 两个来源保真。
- **嵌套列表被扁平化**：`ListBlock` 只表示一层列表，md/docx 的嵌套子项并入父项内容（保留文字与项边界，不还原层级）。
- **版式不保真**：字体/字号/颜色/页眉页脚/分栏/图片均不保留（`reportlab` 只渲染文本结构）。
- **需显式绑定**：智能体要同时绑定 Skill 与 `doc_convert` 工具才生效。
- **产物不回收**：沿用 `24` 的现状，磁盘文件不随会话删除清理。
- **单文件 20MB / 产物 5MB**：沿用附件与产物既有上限。
- **接力回合不可用**：`@` 提及触发的接力回合不携带本轮附件（与既有的 audio/image 注入一致），其中的 `doc_convert` 会返回「没有可转换的文档附件」。

## 25.7 决策记录

- 用户明确要求「产出真实可下载文件，且 pdf/docx 能在纪要处预览」，据此把 `19` 的纯指令包形态升级为「工具 + 产物」。
- 引擎在「纯 Python / pandoc+typst / LibreOffice」三者中选定**纯 Python**：宿主与容器一致、无系统依赖、镜像增量最小（用户确认）。
- docx 预览用后端 `mammoth` + 前端 `sandbox iframe`，而非引入 `mammoth.js` 或 `DOMPurify`（用户确认可加依赖，但此处零前端依赖更简）。
- 设计文档编号 `25`（`19` 保留，不覆盖；`19` 增加指向本文的说明）。

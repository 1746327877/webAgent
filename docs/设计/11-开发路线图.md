# 11 开发路线图（M0 → M6，约 8 周）

> 排序原则：**最高技术风险最先打通**（M0 的 Ollama 流式连通），**面试价值最高的模块尽早成型**（M3 检索、M5 可观测性）。每期结束产出可演示增量。

## M0 骨架与风险打通（第 1 周）

| 任务 | 验收标准 |
|---|---|
| 仓库 init、lint/format/CI、Alembic 空迁移 | CI 绿 |
| users 表 + JWT 注册/登录/刷新 | Swagger 可登录 |
| 前端 Shell（布局/路由/登录页） | 浏览器可登录进空工作台 |
| **ModelProvider 雏形 + Ollama 连通 + 裸流式聊天页**（无持久化） | 浏览器看到 token 逐字输出 ← **最高风险点** |

## M1 会话 MVP（第 2~3 周）

| 任务 | 验收标准 |
|---|---|
| sessions/messages/attachments 表 + 迁移 | — |
| SSE 类型化事件协议（Emitter）+ 消息持久化 | 刷新后历史完整 |
| blocks 渲染（markdown/代码高亮/工具占位） | 代码块带复制按钮 |
| 消息操作：复制/重新生成/停止 | 停止后部分内容保留 |
| 侧边栏会话列表：搜索/时间分组/置顶/归档/删除 | 千条会话列表不卡 |

## M2 智能体系统（第 3~4 周，与 M1 交叠）

| 任务 | 验收标准 |
|---|---|
| 智能体 CRUD + 配置表单（参数滑杆/模型下拉） | Pydantic 校验生效 |
| 工具注册表 + `time_now`/`kb_search`(空实现先行) | 模型成功发起 tool_calls 并回填结果 |
| 版本：发布快照/回滚/消息级 agent_version | 回滚后新会话用旧配置 |
| 欢迎语/标签/示例问题 | 空会话状态展示 |

## M3 知识库 RAG（第 4~5 周）

| 任务 | 验收标准 |
|---|---|
| 上传 + ARQ 解析/切片/嵌入流水线（状态机） | PDF/MD 入库 → ready 徽章 |
| jieba FTS 列 + 双索引 + RRF 混合检索 SQL | 混合查询命中兼顾语义与关键词 |
| 引用注入 + citation 事件 + 角标/卡片/抽屉 UI | 答案可点开原文 |
| agent_kbs 绑定 + 检索 span 记录 | 后台可见检索得分 |

## M4 模型调度与协作（第 5~6 周）

| 任务 | 验收标准 |
|---|---|
| ModelManager 状态机 + acquire 接入 Runtime | 跨模型会话自动接力切换 |
| 显存值守（/api/ps + nvidia-smi 采样）+ 后台"模型管理"页 | 显存曲线可见，手动加载/卸载可用 |
| `@` 提及（前端弹层 + 接力协议） | A 答 → B 接力，头像区分 |
| 多模态：图片上传 → VL 模型按需加载（*可砍*） | 发图获描述 |

## M5 后台与可观测性（第 6~7 周）

| 任务 | 验收标准 |
|---|---|
| spans 全埋点（llm/tool/retrieval/model_switch）+ HTTP 计数 | 任一会话可还原完整调用链 |
| 聚合物化视图 + 全局仪表盘（ECharts 五件套） | 指标与实际请求对得上 |
| 会话详情 waterfall + JSON 树 + 工具日志筛选/CSV 导出 | 30 秒演示脚本可跑 |
| 告警规则 + 评估任务 + 站内通知（*可砍*） | 人为压测触发红点 |

## M6 打磨与发布（第 7~8 周）

| 任务 | 验收标准 |
|---|---|
| R1 thinking 解析 + 折叠 UI（若 M1 已埋事件则顺滑） | R1 会话思考链可折叠 |
| OpenAI 兼容端点 + API Keys 管理 | 标准 SDK 调通智能体 |
| Docker 化全链路 + README（架构图/GIF/一键启动） | 陌生机器 `docker compose up` 可跑 |
| 虚拟滚动/降级渲染/主题/空态/错误态打磨 | Lighthouse 性能 ≥ 85 |
| seed 数据 + 录制 30 秒演示视频 | — |

## 可砍项优先级（时间不足时从上往下砍）

1. 多模态（M4）
2. 告警（M5）
3. API Keys + OpenAI 兼容端点（M6）
4. `web_search`/`http_request` 工具（保留 `kb_search`+`time_now` 即可演示 function calling）

## 风险清单

| 风险 | 缓解 |
|---|---|
| Ollama 流式/function calling 行为与预期不符 | M0 即验证；Provider 层隔离，最坏可切 openai_compat |
| VL 7B 在 12GB 显存吃紧 | num_ctx 降到 4K；或换 qwen2.5vl:3b；再不行砍多模态 |
| 乒乓切换导致体验差 | model_switching 事件管理预期 + 切换频率监控 + 会话归组提示 |
| jieba FTS 召回不达预期 | RRF 双通道互补；调 top_k；黄金问答集驱动调参 |
| 8 周排期过满 | 可砍项清单兜底；M1/M2 并行推进 |

## 第二期（可选，D8 决策）：Open WebUI fork 二开

Phase 1（M0~M6）完成并打磨后启动，预计 **3~4 周**。立项时再细化范围，原则：

- 从 **显存看板 / @接力协作 / span waterfall** 中挑 1~2 个亮点移植进 Open WebUI（带 Phase 1 认知做"第二次实现"，效率高）；
- 评估将其中社区真正需要的能力以 **PR 回馈上游**（151k star 项目的 contributor 记录，简历价值极高）；
- Phase 1 期间 Open WebUI 仅作日常工具 / 源码参照 / 面试选型对比素材，**零改造成本**。

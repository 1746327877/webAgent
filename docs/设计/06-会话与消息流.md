# 06 会话与消息流

## 6.1 AgentRuntime 执行循环（后端最核心一段）

```
POST /api/v1/sessions/{sid}/messages   →  立即返回 SSE 流

1. 落库用户消息（blocks=[text], mentions 解析, attachments 关联）
2. 构建上下文：
   a. system = 系统提示词(变量插值) + 知识库检索结果(有绑定时, 记 retrieval span)
   b. history = 最近 history_rounds 轮, 按 token 预算裁剪(从旧往新丢)
   c. tools  = 智能体绑定工具的 function 定义
3. model_manager.acquire(主模型)          ← 可能触发切换 → SSE model_switching
4. while True:  (ReAct 循环, 上限 5 轮)
     provider.chat_stream(...) 逐事件转发 SSE 并累积 blocks
     ├─ thinking → block{thinking}
     ├─ token    → block{text} 追加
     ├─ tool_call → 执行工具(记 tool span, 输入输出截断入库)
     │              结果作为 tool 角色消息回填 → continue 下一轮
     └─ 无 tool_call → break
5. 收尾：usage/span 落库、title 自动生成(首轮)、done 事件
6. 异常：error 事件 + error span（仪表盘错误率数据源）→ status=error
```

关键实现（节选）：

```python
async def run_agent_turn(session, user_msg, emit: Emitter):
    agent = session.agent
    cfg = agent.model_config
    # 1~2 上下文构建
    messages = [{"role": "system", "content": await build_system(agent, session, emit)}]
    messages += await trim_history(session, rounds=cfg.history_rounds)
    messages += [{"role": "user", "content": user_msg.blocks_to_text()}]

    async with spans.trace(session_id=session.id, agent_id=agent.id) as trace:
        await model_manager.acquire(cfg.model, on_switch=emit.model_switching)
        for iteration in range(MAX_TOOL_ROUNDS):           # 5 轮防死循环
            req = ChatRequest(model=cfg.model, messages=messages,
                              tools=tools_payload(agent), **cfg.gen_kwargs())
            final_blocks, tool_calls = [], []
            async for ev in provider.chat_stream(req):
                block = await emit.forward(ev)             # SSE + 累积 blocks
                if ev.type == "tool_call":
                    tool_calls.append(ev.payload)
                if ev.type == "usage":
                    trace.record_usage(ev.payload)
            if not tool_calls:
                break
            messages.append(assistant_msg_with_tools(final_blocks, tool_calls))
            for call in tool_calls:                        # 串行执行工具
                result = await execute_tool(call, agent, trace)   # 记 tool span
                messages.append({"role": "tool",
                                 "content": truncate(result, 8_000)})
                await emit.tool_result(call, result)
    await finalize_message(...)                            # blocks/usage 落库 + done
    await relay_to_mentions(user_msg.mentions, session)    # ★ @接力（见 6.3）
```

**SSE 服务端骨架**：

```python
@router.post("/{sid}/messages")
async def post_message(sid: UUID, body: MessageIn, user=Depends(get_current_user)):
    session = await sessions_repo.get_owned(sid, user)      # 隔离校验
    queue: asyncio.Queue[ServerEvent] = asyncio.Queue()

    async def producer():
        try:
            await run_agent_turn(session, body, emit=Emitter(queue))
        except Exception as e:
            await queue.put(ServerEvent("error", {"message": str(e)}))
        finally:
            await queue.put(ServerEvent("done_sentinel", {}))

    task = asyncio.create_task(producer())
    async def gen():
        while (ev := await queue.get()).type != "done_sentinel":
            yield f"event: {ev.type}\ndata: {json.dumps(ev.data)}\n\n"
    return StreamingResponse(gen(), media_type="text/event-stream",
                             headers={"X-Accel-Buffering": "no"})  # 防 nginx 缓冲
```

### 6.1.1 每轮可选开关（请求体）

`MessageIn` 里除 `content / mentions / attachment_ids` 外，还有三个**只影响本轮**的开关（都不持久化）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `model_override` | `str?` | 临时覆盖本轮模型（有图时视觉模型优先） |
| `web_search` | `bool` | 本轮是否挂联网搜索 MCP 工具（见 [[18-联网搜索开关]]） |
| `thinking` | `bool?` | **三态**深度思考：`None`=不改动（用模型默认）／`true`=开／`false`=关；最终下发给 Ollama 的 `think` 参数 |

`thinking` 为什么是三态而不是布尔：**非思考模型收到 `think` 参数会报错**，所以"模型是否支持"由前端按 `/api/v1/models` 的 `capabilities`（含 `"thinking"`）判断——不支持时按钮置灰、且**不上报该字段**。实测（`qwen3.5:9b`）：`think=false` 不产出思考、直接作答；`think=true` 思考会占用 `num_predict` 预算（默认 2048 容易被吃光导致正文为空）。

## 6.2 消息 blocks 结构（JSONB 约定）

```jsonc
[
  { "type": "thinking", "content": "…", "duration_ms": 3120 },
  { "type": "text",     "content": "根据检索结果 [1]…" },
  { "type": "tool_call",    "id": "c1", "tool": "kb_search", "args": {"query": "…"} },
  { "type": "tool_result",  "id": "c1", "status": "ok", "elapsed_ms": 820,
    "preview": "…前200字…" },                    // 全文进 spans.output，消息里存预览
  { "type": "citation", "ref": 1, "chunk_id": "c_42", "source": "Java并发编程.pdf",
    "page": 12, "score": 0.87, "snippet": "…" },
  { "type": "transcript", "name": "voice.mp3", "text": "…", "status": "ok" }  // 音频附件转写（见 23）
]
```

- 前端按数组顺序渲染：`thinking` → 折叠面板，`text` → markdown，`tool_*` → 工具卡片，`citation` → 角标，`transcript` → 🎙️ 折叠块。
- 流式时 blocks 在内存累积、每 100ms 批量 flush 落库（防高频写）。

## 6.3 `@` 接力式协作协议

> 单显存约束下所有协作本质是**串行换模型**（决策 D5，见 [[00-项目总览]]）。

- 用户消息携带 `mentions: [agentB_id]`（前端 `@` 弹层选择，见 [[09-前端交互设计]]）。
- 主智能体（会话归属者）正常回答完毕后，Runtime 依次处理 mentions：

```
for mentioned_agent in mentions:
    emit(agent_turn_start, mentioned_agent)
    await model_manager.acquire(mentioned_agent.model)   # 接力换模型
    上下文 = 完整会话历史(含主智能体刚产出的回答) + 指令后缀
             ("你是 {mentioned_agent.name}，用户 @ 了你，请针对上文补充你的专业意见")
    走同一套 ReAct 循环（工具/知识库按被@智能体自己的绑定）
    产物消息 agent_id = mentioned_agent.id   ← 前端按头像区分发言者
```

- 每条接力消息头部显示「接力自 @名字」；`model_switching` 事件让前端浮"正在切换到 xxx"提示。
- MVP 限制：单条消息最多 @ 2 个智能体（防超长等待）；接力过程中用户可 `stop`。

## 6.4 其他关键流程

| 流程 | 实现 |
|---|---|
| **停止生成** | `POST /messages/{id}/stop` → 置 `CancelledEvent`；Runtime 各 `await` 点检查；已生成 blocks 照常落库，`status=stopped`，usage 记到停止时刻 |
| **重新生成** | `POST /sessions/{id}/regenerate {message_id}` → 服务端截断该消息及其后 → 重跑同一轮（复用 6.1 逻辑） |
| **编辑重发** | 前端编辑用户消息 → `PATCH` 该消息 blocks + 服务端截断后续 → 触发重新生成 |
| **标题生成** | 首条用户消息后，ARQ 任务用**主力模型**生成 ≤16 字标题（低温度），失败回退"截取首行" |
| **历史裁剪** | `history_rounds` 轮 + token 预算（`num_ctx` 的 1/3）双保险，超预算从最旧丢弃 |
| **多模态** | 用户消息附图 → `attachments.kind=image` → 构建消息时 images 进 OpenAI 格式 `image_url`(base64) → Runtime acquire VL 模型（`qwen2.5vl:7b`）回答 → 回到原模型（全程 model_switching 事件） |

# 16 · 智能体头像 与 新建时配置扩展能力

> 状态：设计已定，实施中
> 关联：`04-智能体管理模块.md`、`12-扩展能力与MCP.md`、`13-...`、`09-前端交互设计.md`

## 16.1 背景与目标

1. **新建智能体时无法配置扩展能力**：智能体编辑器的「扩展能力」标签只在已有 agent（有 id）时出现，因为绑定接口都是 `/agents/{id}/skills|mcp-tools|tools`。
2. **头像**：现在只有 `emoji` 字段；需要支持上传头像图片，未上传时用**智能体名字的第一个字**作为头像。

## 16.2 决策（已确认）

| 事项 | 决策 |
|---|---|
| 头像兜底 | **有头像用头像，否则用名字首字**；`emoji` 字段保留在库/接口中（不删、兼容旧数据），但界面不再展示与填写 |
| 新建扩展能力 | **先在前端攒着，创建成功后自动写入**（依次 PUT tools/skills/mcp-tools，并上传头像）；部分失败会明确告知 |

## 16.3 后端

### 16.3.1 头像存储

- `agents` 表新增 `avatar_path`（可空，存"落盘文件名"`{uuid}.{ext}`，与附件一致，落在 `settings.upload_dir`）。
- 新增 `app/core/upload_rules.py`：集中图片校验规则（`IMAGE_EXTS` / `MAGIC_PREFIXES` / `MAX_IMAGE_BYTES` / `ensure_valid_image()`），**附件上传复用同一套**（消除重复）。

### 16.3.2 头像接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/agents/{aid}/avatar` | multipart 上传；校验扩展名/大小/魔数；替换时删除旧文件 |
| DELETE | `/api/v1/agents/{aid}/avatar` | 清除头像并删除文件 |
| GET | `/api/v1/agents/{aid}/avatar` | 返回图片（鉴权 + 归属校验，`<img>` 不能带 Bearer，前端以 blob 方式取） |

- `AgentOut` 增加 `has_avatar: bool`（前端据此决定是否拉图；版本变化由 `updated_at` 参与缓存失效）。

## 16.4 前端

- `components/agents/AgentAvatar.tsx`：统一头像组件 —— 有 `has_avatar` 时经鉴权拉 blob 显示图片；否则显示**名字首字**（并按名字做确定性配色）。
- 替换所有 emoji 展示点：智能体列表、编辑器标题、侧栏「选择智能体新建」、聊天头部/落地页/欢迎区、消息徽标、提及下拉、可观测性会话记录。
- `AgentForm`：Emoji 输入改为**头像上传**（点击选择图片、本地预览、可移除）。
  - 编辑态：选图即上传（独立资源）+ toast。
  - 新建态：先在本地持有 `File`，创建成功后上传。
- **新建时配置扩展能力**：
  - 抽出受控选择器：`SkillSelector` / `McpToolSelector`（`ToolsMatrix` 本就是受控）——编辑态与新建态共用，避免重复。
  - 编辑器对新建智能体也显示「扩展能力」标签，选择结果存在页面 state；
  - 提交顺序：`POST /agents` → `PUT /agents/{id}/tools` → `PUT /skills` → `PUT /mcp-tools` → `POST /avatar`；任一步失败都在 toast 里说明是哪些没存上，不影响已创建的基础信息。

## 16.5 测试

- 后端：头像上传（成功/类型不支持/超限/魔数不符）、替换删除旧文件、删除头像、越权 404；`ensure_valid_image` 单测。
- 前端：`AgentAvatar`（有头像走 blob、无头像取名字首字、空名字兜底）；`AgentForm` 头像选择与移除；新建流程串联保存（mock 各 mutation，断言调用顺序与参数）。

## 16.6 已知限制

- 头像不做裁剪/压缩（仅限制类型与 2MB 大小）。
- `emoji` 字段保留但不再展示，历史数据不迁移。
